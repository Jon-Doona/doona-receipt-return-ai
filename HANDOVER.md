## 1. What This App Does

Doona is an internal company tool for **Doona employees** to submit travel-expense receipts.

**Workflow:**
1. Employee enters their email on the landing page (no password, no Supabase Auth).
2. Employee fills out a trip form (name, role, country, purpose, dates, itinerary).
3. The app creates a **brand-new Google Spreadsheet** (via a Google Apps Script backend) that is a copy of the company's master expense template.
4. Employee drops receipt images. AI (Gemini) reads each receipt and extracts: date, merchant, currency, amount, category, and payment method.
5. Employee reviews the AI output, corrects if needed, and clicks **Save**.
6. The receipt image is uploaded to a shared Google Drive folder, and a row is written into the correct **category section** of the trip spreadsheet — with a hyperlink to the receipt photo.
7. When done, the employee clicks **Finish & email me the report**. The app emails them a summary with links to the spreadsheet and the Drive photos folder.

The spreadsheet is a Hebrew (RTL) expense report with a **summary tab** (`דוח נסיעה לחו"ל`) and an **expense detail tab** (`דוח החזר`). The GAS backend populates both.

```
│  (Deno runtime)            │
│                            │
│  Modes handled:            │
│  • options                 │
│  • gas_proxy  → GAS        │
│  • extract    → AI Gateway  │
│  • upload_drive → Drive    │
│  • send_email → Gmail      │
└──────┬──────────────┬──────┘
       │              │
   ┌───▼────┐    ┌───▼──────┐
   │ GAS    │    │ Lovable  │
   │ (Apps  │    │ AI GW    │
   │ Script)│    │ (Gemini) │
   └───┬────┘    └──────────┘
       │
   ┌───▼────────────────────────┐
   │ Google APIs (via Lovable   │
   │ connector gateway)           │
   │ • Sheets  • Drive  • Gmail  │
   └────────────────────────────┘
```

**Why the Edge Function exists as a middle layer:**
- **CORS bypass:** The Google Apps Script endpoint (`script.google.com`) does not send CORS headers on its redirected response. Browsers cannot read it. The Edge Function calls GAS server-to-server and returns JSON.
- **Secrets:** Google connector API keys and the Lovable AI key live only in the Edge Function env, never exposed to the browser.
- **Rate-limit friendliness:** AI calls that hit 429 can be retried with exponential backoff without the frontend timing out.

## 4. Data Models

### `Trip` (client-side state, cached in localStorage)

```ts
interface Trip {
  spreadsheetId: string;   // The new GAS-created spreadsheet ID
  sheetId: number;         // The gid of the expense detail tab
  sheetTitle: string;      // e.g. "Jane Cohen – Japan – 2026-07-01"
  sheetUrl: string;
  sections: Section[];     // Parsed category sections from the sheet
  traveler_name: string;
  country: string;
  folderId?: string | null;   // Google Drive folder for this trip's photos
  folderUrl?: string | null;
}
```

Cached key: `doona.activeTrip`

### `Receipt` (client-side state)

```ts
interface Receipt {
  id: string;              // crypto.randomUUID()
  file: File;              // Original image file
  previewUrl: string;      // objectURL for UI thumbnail
  status: "pending" | "scanning" | "ready" | "saving" | "saved" | "error";
  date?: string;           // YYYY-MM-DD
  destination?: string;    // City + merchant
  currency?: string;       // ISO code
  amount?: number;
  category?: string;       // One of the 9 Hebrew categories
  payment_method?: "company_card" | "employee";
  driveUrl?: string;       // Link to uploaded Drive file
  savedRow?: number;       // Row number written in sheet
  warnings?: string[];      // UI warnings (e.g. currency mismatch)
}
```

### `Section` (sheet geometry)

```ts
interface Section {
  title: string;           // Hebrew category name
  header_row: number;      // 1-based row index of the "תאריך" header
  first_data_row: number;  // First writable row
  last_data_row: number;   // Last writable row (inclusive, before "סה"כ")
}
```

The Edge Function dynamically scans the sheet to find these sections by looking for the Hebrew word `תאריך` in column C and the totals marker `סה"כ` in column F.

## 5. The Google Apps Script (GAS) Integration

### Why GAS?

The company's master spreadsheet is complex, RTL, and has formulas. Instead of trying to reverse-engineer every cell with the Sheets API, a **Google Apps Script** lives inside the master spreadsheet. It knows the exact cell coordinates and can:
- Create a new spreadsheet from a template
- Fill the header fields (`שם + משפחה`, `תפקיד`, `מדינה`, etc.)
- Fill the itinerary table
- Fill the summary tab (`דוח נסיעה לחו"ל`)
- Write expense rows into the correct category section
- Insert rows if a section is full
- Delete a trip spreadsheet

### GAS Endpoint

```
https://script.google.com/macros/s/AKfycbw1k4_4nMoKPdbMA49F4tY289Ioybprkva1-SbWtd7OwsQP6AJtrdX8kpbB916LAW4/exec
```

**This URL must be kept in sync.** If the GAS project is redeployed, update the `GAS_URL` env var in the Edge Function settings.

### Communication Flow

1. **Frontend** calls the Edge Function with `mode: "gas_proxy"` and a `payload`.
2. **Edge Function** POSTs the payload to the GAS URL with:
   - `Content-Type: text/plain;charset=utf-8`
   - `redirect: follow`
3. **GAS** receives the JSON, acts on it, and returns a JSON response.
4. **Edge Function** parses the response and returns it to the frontend.

### GAS Actions Expected

| `action` | Payload fields | What GAS does |
|----------|---------------|---------------|
| `createTrip` | `clientTripId`, `traveler_name`, `role`, `country`, `purpose`, `from_date`, `to_date`, `business_days`, `itinerary[]`, `user_email` | Creates a new spreadsheet from the template, fills headers + itinerary + summary tab. Returns `spreadsheetId`, `sheetId`, `sheetTitle`, `sheetUrl`, `folderId`, `folderUrl`. |
| `saveExpense` | `spreadsheetId`, `sheetId`, `date`, `destination`, `currency`, `amount`, `category`, `payment_method`, `drive_url` | Finds the correct category section, finds the next empty row, writes the data, inserts a hyperlink in the `אסמכתא` column. Returns `row`. |
| `deleteTrip` | `spreadsheetId` | Moves the trip spreadsheet to trash. |

## 6. AI Extraction (Receipt Scanning)

### Model
- **Provider:** Lovable AI Gateway
- **Model:** `google/gemini-3-flash-preview`
- **Method:** Tool-calling (`extract_receipt` function)

### What AI Extracts
- `date` → `YYYY-MM-DD`
- `destination` → City + short merchant (max 50 chars)
- `currency` → ISO code (from a locked list of 12 currencies)
- `amount` → Positive number, no symbol
- `category` → One of 9 Hebrew categories (exact match)
- `payment_method` → `company_card` or `employee`
- `raw_text` → Verbatim text from the receipt (used for validation)

### Currency Detection (Critical Business Rule)

The AI prompt contains an extremely detailed currency-detection guide. Key rules:
- **Never default to ILS or USD.**
- Use country/language first, then symbols.
- Country defaults: Thailand→THB, Israel→ILS, Japan→JPY, China→CNY, Hong Kong→HKD, USA→USD, UK→GBP, Eurozone→EUR, Switzerland→CHF, Canada→CAD, Australia→AUD.
- Symbol overrides only when unambiguous.

### Validation After Extraction

The backend checks whether the extracted `currency` code actually appears in the `raw_text` the AI transcribed. If not, a **warning** is returned to the frontend and displayed in an amber banner on the receipt row.

## 7. Sheet Structure & Category Mapping

### Locked Categories (Hebrew)

```ts
const CATEGORIES = [
  "טיסות",                       // flights
  "נסיעות בתחבורה ציבורית",     // public transport
  "לינה ללא ארוחות",            // lodging without meals
  "השכרת רכב",                  // car rental
  "אירוח אורחים בחול",          // client entertainment abroad
  "תקשורת",                     // telecom
  "ארוחות",                     // meals
  "הוצאות שונות",               // miscellaneous
  "ללא קבלות",                  // no receipts
];
```

### Locked Currencies

```ts
const CURRENCIES = [
  "ILS", "USD", "EUR", "GBP", "JPY",
  "CHF", "CAD", "AUD", "CNY", "RMB", "HKD", "THB"
];
```

### Payment Methods

- `company_card` → Hebrew label: `כ. אשראי חברה`
- `employee` → Hebrew label: `העובד`

### Column Layout (Expense Detail Tab)

The sheet is RTL. The data columns (left-to-right visually, but RTL context):
- **Col C (index 2):** Date (`תאריך`)
- **Col D (index 3):** Destination / Merchant
- **Col E (index 4):** Currency
- **Col F (index 5):** Amount
- **Col H (index 7):** Paid By (`מוסד התשלום`)
- **Col I (index 8):** Receipt Reference (`אסמכתא`) — contains `=HYPERLINK(...,"קבלה")`

### Auto-Expansion

If a category section is full (all rows have dates), the backend **inserts a new row** before the totals row (`insertDimension` in the Sheets API) so the receipt can still be saved.

## 10. Important Gotchas & Edge Cases

### 1. GAS CORS
The GAS endpoint does **not** send CORS headers. **Never** call it directly from the browser. Always route through the Edge Function's `gas_proxy` mode.

### 2. GAS Redirect
When fetching the GAS URL, the Edge Function uses `redirect: "follow"` and reads the final response body as text, then tries `JSON.parse()`. If GAS is redeployed, the URL changes — update `GAS_URL` immediately or the `createTrip` flow breaks.

### 3. Optimistic Advance
In `startNewTrip()`, if the GAS proxy call fails (network hiccup, timeout), the frontend still advances the user to the upload step with an **optimistic** trip object. The `spreadsheetId` becomes the `clientTripId` (a local synthetic ID). This means:
- The user can keep uploading.
- But if the sheet was never actually created server-side, saving receipts will eventually fail with a "not found" error.
- This is a deliberate UX tradeoff to avoid blocking workers on flaky networks.

### 4. Rate Limiting (AI)
The AI gateway may return `429`. The frontend handles this with:
- A **sequential scan queue** (not parallel) — only one AI scan runs at a time.
- A **2.5s delay** between scans.
- **Exponential backoff** on 429: starts at 15s, doubles up to 120s, up to 30 retries.
- The user sees "AI is busy — waiting and retrying automatically."

### 5. Drive Upload Batch Size
When saving receipts, the frontend processes them in **batches of 3** (`WORKERS = 3`). This keeps Drive and Sheets API pressure reasonable while still being faster than fully sequential.

### 6. Start Over = Nuclear Option
Clicking **Start Over**:
- Calls GAS `deleteTrip` to trash the spreadsheet.
- Clears `localStorage`, `sessionStorage`, and **all IndexedDB databases**.
- Revokes object URLs for receipt previews to prevent memory leaks.
- Resets all form state.

### 7. Sheet No Longer Exists
If a user tries to save to a sheet that was deleted (e.g. they clicked Start Over in another tab), the backend returns an error containing `"No grid with id"` or `"not found in sheet"`. The frontend catches this, shows a toast, and kicks the user back to trip setup.

### 8. Business Days Calculation
Calculated in the Edge Function (`calcBusinessDays`). Counts Mon–Fri inclusive between two dates, excluding **Friday and Saturday** (Israeli weekend). This value is passed to GAS and written into the sheet header.

## 12. Common Maintenance Tasks

### Adding a New Currency
1. Add it to `CURRENCIES` array in `supabase/functions/scan-receipt/index.ts`.
2. Add it to the AI system prompt's currency list (in the `extract` mode).
3. Add symbol mappings to the `symbolMap` in the validation block.
4. Deploy the Edge Function.

### Adding a New Category
1. Add it to `CATEGORIES` in the Edge Function.
2. Add mapping logic in the AI system prompt (the `category MUST be one of...` line).
3. Update the GAS script to recognize the new section header in the template.
4. Deploy both.

### Changing the GAS URL
1. Update the `GAS_URL` (or `GOOGLE_SCRIPT_URL`) secret in the Edge Function env.
2. Redeploy the Edge Function.
3. Update this document.

### Updating the Master Template
If the company's master spreadsheet template changes (new rows, new columns, different layout):
- **The GAS script must be updated first** because it hardcodes cell coordinates.
- The Edge Function's `loadSections` and `readSectionDates` logic may also need adjustment if the column positions of `תאריך` or `סה"כ` change.
